# UX 2.2 implementation owner (approved)

This supplements, without replacing, `docs/blueprints/first-functional-release.md`, the
compatibility amendment and the approved UX 2.0/2.1 contracts in tempgpt#31.

## Decisions

- First clean import defaults to the neutral **Original** offline destination. No platform is
  inferred from pixels; explicitly remembered valid destinations remain. Every fresh session
  still defaults to PNG and identifying-metadata removal.
- Automatic exposes PNG and lossless WebP; destination PNG-only constraints disable WebP.
  Explicit individual format overrides remain reviewable, never overwritten silently.
- Settings uses a full-screen dialog with a single vertical scroll owner and stable Close.
  Its actual swipe behavior still needs physical Pixel validation.
- A fully verified and unchanged export opens a single action surface for View, Share and
  New work. Existing journal-backed acknowledgement remains the only draft-retirement path.
  Partial/uncertain/stale jobs stay in technical review; no auto-retry or deletion.
- The in-app viewer decodes a bounded 1600-pixel sample from a verified published content URI,
  never the user's original or an unverified output, without new storage permissions.
  External Android VIEW remains a fallback.
- `FitMode.FLEXIBLE` has separate `FrameFocus` values and geometry, distinct from historic
  `FitMode.CROP` / `CropFocus`. Its output rectangle can extend beyond a fixed-ratio
  canvas (real clipped source) or leave a genuine matte. One original source bitmap is drawn
  at native pixel size, positioned into the output and clipped naturally by the renderer.
  Below-fill zoom alters the canvas within the same selected ratio, up to full containment.
- The existing CropPlanner is not weakened, nor is an existing saved crop reinterpreted.
  New frame coordinates persist as optional fields in draft schema1; absent fields default
  to neutral frame state. The existing frozen output digest is extended ONLY if an actual
  flexible-frame recipe is present, preserving legacy version2 identities and safe retries.
  Exact-size flexible framing is blocked for explicit review rather than resized silently.
- Per-pointer edits remain local to a retained canvas; the ViewModel draft/undo is published
  only when the gesture ends. Preview and final export consume the same planned native
  placement. The "excluded" view never becomes an output image.

## Acceptance / status

All changes stay on the open draft PR `release/0.1.0-editor` pending one accumulated
current-source Android build/lint/API36 smoke. No test count/physical performance or APK is
accepted before actual CI evidence; Android API26 legacy SAF, real Pixel full-res pixel/color,
TalkBack/200% fonts and native codec hardware, 16KiB, signing/provenance and release
gates remain open. No merge, key, permission, telemetry, network or publication.

## UX 2.2 diagnostic delivery guard — 2026-10-29

The original UX 2.1 Touch APK and newer UX 2.2 debug builds share `.touch` but
are signed by different ephemeral CI keys; Android cannot treat the latter as an
update. Keep earlier diagnostics and app-private state intact. The UX 2.2 debug
variant therefore uses the isolated `org.cajapersonal.fixmyshot.ux22` ID and
`FixMyShot UX 2.2` display name, with no change to the release application ID,
version ledger, production signing plan or permissions. Its Android smoke script
must exercise the same isolated ID. Frame zoom/crop hints must describe the
actual flexible output instead of claiming the complete original remains visible
when pixels are trimmed. Artifact screenshots must be genuine named captures:
`editor-framing.png` is copied from the Focus test, never overwritten by later
Settings screenshots; missing optional captures are omitted, not disguised as PNGs.

## Post-export editing diagnostic

After the Continue editing correction passed its exact-source API36 checkpoint, a
separate `.ux22edit` / `FixMyShot UX 2.2 Edit` debug package provides the next phone
handoff. It retains the accepted `.ux22` installation and its private draft; it is
not an in-place upgrade and starts with separate app settings. The correction and
tests are unchanged. Smoke scripts follow the new diagnostic package. Production
application ID, version ledger and signing plan remain unchanged. Source-bound
build, runtime and APK integrity/signature checks still precede delivery.
