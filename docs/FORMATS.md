# Codec status

## Initial Phase 1 slice

| Output | Implemented route | Current acceptance boundary |
|---|---|---|
| PNG | Android PNG encoder on API 26+ | Synthetic instrumentation asserts opaque RGB / alpha RGBA, container CRCs, independent reopen and exact normalized pixels. Runtime/device results must come from the matching CI/device report. |

A bounded Photo Picker import/review path accepts supported static SDR JPEG, PNG and WebP sources. That is not yet a full production export pipeline; JPEG output is excluded. Unsupported selections return typed errors and are never replaced with another format.

## Adapter limits

Inputs must already be ARGB_8888, SDR sRGB, oriented and within 24 megapixels plus the lower dynamic memory budget. WebP also enforces its 16,383-pixel side limit. These checks do not promise support for every in-range image. Working-set estimates are provisional; Java/native/PSS peak measurements are still required.

The low-level PNG/WebP encoder receives pixels only, not source EXIF/XMP. The source-aware private export pipeline can subsequently write the explicit preservation allowlist described below. Semi-transparent edge/color fidelity, all EXIF orientations, HDR handling and payload-preserving no-op exports remain later acceptance work. The current synthetic alpha fixtures cover transparent/opaque edges, not the full semi-transparent color contract.

The immutable PNG/WebP preflight binds staged source SHA-256, geometry, per-item/session revisions, format, metadata policy and provisional memory estimates; the test-only private executor rehashes staged source bytes before and after encoding, decodes original oriented SDR pixels (not a preview), applies the contained geometry, freezes the automatic edge background and invokes LosslessEncoder. Its generated PNG/WebP candidates must pass strict chunk/signature/dimension/metadata allowlists and bounded decoder reopening; failure removes the candidate. This is NOT a public export transaction or proof of complete metadata/color fidelity. The experimental API29+ owned MediaStore adapter implements IS_PENDING publication, app-private atomic single-item checkpoints, copy digest validation and conservative indeterminate outcomes; the explicit development Export action now invokes it. A synthetic test may create and immediately delete its own gallery item. The development branch now wires an experimental explicit Export button to per-item MediaStore29+ or user-chosen SAF output, with serialized private encoding and localized progress/results; the exact-source build/API26/API36 synthetic export/share checks passed at 3df5262 (see docs/TESTING.md). Automated or manual acceptance for mixed 100-item export, crash reconciliation, folder grant durability, physical providers/gallery and share chooser is still missing. A separately gated internal SAF tree-output adapter permits only an explicitly selected folder, never silently labels it Pictures/FixMyShot, and records that a SAF document can be visible while bytes are still being written. The API26–28 folder picker and persisted read/write grant check are wired, but actual selected-folder/provider and grant-recovery tests remain NOT RUN. Permission-mediated default Pictures saving on those APIs is still unimplemented; explicit SAF selection does not close that blueprint requirement. PNG/platform WebP cancellation is checked at output writes and after encode, not guaranteed instantaneous within platform code. Native WebP also checks progress and scanline preparation. Timeout tests and measured cancellation latency remain open.

## Native writer candidate

The AndroidX 1.2.0-rc01 writer AAR declares `minSdk 29`; FixMyShot keeps app `minSdk 26`. The app uses the manifest merger's exact-package `tools:overrideLibrary="androidx.heifwriter"` only because native HEIC paths are entered at API 29+ and AVIF paths at API 34+, and no library writer code may be invoked on lower APIs. This exception is a **build-time compatibility mechanism, not evidence of runtime safety**; API 26 launch/PNG/WebP/native rejection tests and API 36 real encoding probes are mandatory acceptance gates. If API 26 fails, remove the exception and restore the last verified build. No `minSdk` increase or format substitution is allowed.

`NativeStillEncoder` uses `androidx.heifwriter:heifwriter:1.2.0-rc01`, a release candidate selected after comparison with stable 1.1.0: the 1.2 line contains material color-aspect and AVIF encoding fixes. It runs only off the main thread, accepts normalized opaque ARGB_8888 SDR sRGB pixels, refuses unsupported API/alpha/metadata policy/resource requests, uses AndroidX bitmap-input writers with quality 100 and a single still, and verifies ISO BMFF brand and platform reopened dimensions/MIME before retaining a candidate. A valid container brand and readable image dimensions are not sufficient: the adapter must also decode actual pixels (with bounded sampling for large inputs) before retaining an output. A decoder failure returns `INVALID_OUTPUT` and deletes the candidate, rather than counting it as native capability. From source `fab2c362`, the bounded verification tries BitmapFactory first and ImageDecoder (API 28+, only through the API29/34 native route) if necessary; both failing still rejects the file. This is a diagnostic decode alternative, not a declaration that the emulator or any device supports these formats. Exact-source Actions run 39609785200 passed its build/API26/API36 instrumentation and preserved lossless output, but both native 65x67 HEIC/AVIF probes on the API36 emulator still reported INVALID_OUTPUT. The alternative therefore remains experimental and does not justify exposing the formats as available. The later bounded geometry probe on API 36 (Actions 39618903599, source 986aee43) generated and independently reopened exactly one 64×64 HEIC file, but the 65×67 HEIC case and both AVIF sizes remained INVALID_OUTPUT. That tiny 8-bit 4:2:0 HEIC lacked an explicit color profile, and independent decoders measured roughly 20 dB RGB PSNR on the high-frequency synthetic pattern. Encoder component advertisements under video MIME are not proof of still-image functionality. This is a source-bound diagnostic success, not color/fidelity acceptance or general HEIC support; see docs/TESTING.md. Device-specific output and appearance still require independent validation. `NativeCodecProbeTest` now compares even 64×64 with odd 65×67 synthetic opaque input for each native format, retaining outputs only after pixel decode and real container checks. It records the platform's advertised HEVC/AV1/still-image codec components separately from the four actual encode results. Empty codec inventory entries and real encoding failures remain distinct; either way, no device capability is promised without actual readable output. These routes are not yet exposed through an import/edit/export UI. Native writer cancellation is cooperative at boundaries and mid-encode latency remains an open G1 gate. **Quality 100 does not mean lossless.**

The separate `NativeGridDiagnosticTest` (source `28aa20b8`) explores grid-disabled odd/even writes plus 66x68 edge-replicated padding of 65x67. Its grid-on setting is a request, not proof that AndroidX actually tiled a small image. AndroidX HeifEncoder/AvifEncoder use 512-pixel grid thresholds and may auto-disable small-grid requests or force tiling for a size unsupported by the underlying HEVC/AV1 video codec. Width alignment without tiles may be to 32/64-pixel codec blocks; test output must preserve visible dimensions. Successful diagnostics report decoded dimensions, synthetic RGB PSNR and channel-error medians, while explicitly marking actual embedded ICC/nclx color tag inspection as **not performed**. These are test-only encodes; no padded geometry, experimental grid mode or uncalibrated color result is promoted into the product writer. The initial grid run compiled and passed API 36, but failed API 26 test-class discovery because a direct ImageDecoder API 28+ reference was unavailable to JUnit reflection on Android 8. A separate API-gated decoder helper was committed in `fa6dd24`, and exact-source Actions run `39631701532` subsequently passed build and both API 26/API 36 emulators, including eight correct API 26 typed native rejections and unchanged API 36 diagnostic results. The API 36 experimental results show 64x64 HEIC and edge-padded 66x68 HEIC outputs, while unpadded 65x67 HEIC and all AVIF attempts failed. The 66x68 outputs were byte-identical between grid requests and had low synthetic ROI PSNR; **neither means reliable color/grid support or an acceptable 65x67 export**. See the exact source-bound evidence in `docs/TESTING.md`. Neither HEIC nor AVIF is yet generally enabled.

## Eligible payload-preserving copies

An unchanged normal-orientation8-bit RGB/RGBA PNG or static lossless WebP may use a bounded metadata-stripping container copy, preserving compressed image payload instead of re-encoding it. Full source/candidate verification and transactional publication still apply. Unknown/profile-bearing/noncanonical appearance data, a changed format, crop/padding/size or compositing requirements keep the existing rendered path. PNG EXIF/text/time and WebP EXIF/XMP are removed on eligible copies; unsupported structures are never silently treated as sanitized. Explicit metadata-preservation opt-out uses the rendered allowlist path below; it never uses this payload copy.

PNG/WebP EXIF orientation is now normalized using the existing AndroidX reader, and PNG animation/recognized HDR signalling is rejected before static processing. The new source-bound tests must pass before runtime acceptance; this does not claim complete HDR, ICC, all-format orientation or physical-device fidelity.


## Selective metadata preservation — PNG and lossless WebP

Review exposes “Remove identifying metadata”, enabled for every new session. Turning it off is an explicit batch or per-image choice; existing per-image overrides remain independent. The warning appears before export and explains that location and identity may be disclosed. This choice is stored only with the current/frozen export session, never as a new-session preference. Native HEIC/AVIF/JXL preservation remains unavailable.

AndroidX ExifInterface1.4.2 reads source fields individually and writes them into a fresh, verified rendered candidate. Preservation is best effort for printable ASCII values of1–512 characters that the pinned writer accepts; missing/unsupported values are omitted. No complete EXIF/XMP/IPTC block, filename or path is attached. Exact supported source tag set:

| Source fields | EXIF tags |
|---|---|
| Capture/digitization time | DateTimeOriginal, DateTimeDigitized, OffsetTimeOriginal, OffsetTimeDigitized |
| Camera/lens | Make, Model, LensMake, LensModel |
| Attribution | Artist, Copyright |
| Location | GPSLatitudeRef, GPSLatitude, GPSLongitudeRef, GPSLongitude, GPSAltitudeRef, GPSAltitude |

DateTime is derived only from retained DateTimeOriginal, never from a source editing timestamp. ImageWidth/ImageLength and PixelXDimension/PixelYDimension are regenerated from the actual output, and Orientation is1. MakerNote, device/lens/body serials, image IDs/digests, thumbnails/previews, comments, editor history, arbitrary XMP/IPTC and source paths are excluded. This is not exact metadata preservation or a promise that all readers display these fields.

After writing, individual values and technical fields are reopened and compared. Independent PNG/WebP structure verification permits exactly one bounded EXIF area (at most64KiB), the closed TIFF tag sets above plus technical dimensions/orientation and directory pointers, and no next-image/thumbnail/interoperability directory. Unknown fields, duplicate/cyclic directories, invalid offsets, stale dimensions/orientation and unrelated container metadata reject the candidate before publication. Default-removal validation still rejects EXIF altogether. Failed preservation is an item failure, never a silent change to the user's selected privacy policy. Source hashes are rechecked and original files are read only.

The bounded synthetic Android36 metadata writer/container path passed at d6b63ae; see TESTING.md for the exact receipt and remaining color/native/hardware limits.
